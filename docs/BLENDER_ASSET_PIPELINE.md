# Blender asset pipeline (3D walk)

The 3D walk draws its plants, rocks, buildings, pieces and props from models made in Blender.
They are original: every mesh and texture is generated by the Python scripts in
`assets/blender/` (fixed seeds, no downloaded art), saved as editable `.blend` sources and
exported as GLB files the game loads. Each slot keeps a procedural fallback, so the walk still
works if a file is missing.

DECISIONS #31 explains the choices; this file is the how-to.

## 1. Where things are

| What | Where |
|---|---|
| Build scripts | `assets/blender/build.py` (entry), `common.py` (mesh builder, materials, AO bake, export), `textures.py`, `flora.py`, `rocks.py`, `village.py`, `homes.py` (the enterable cottage, hall and mill, called by `village.py`) |
| Room plans | `apps/web/src/components/world/buildings.json`: one plan per enterable building (room size, walls, doors, windows, furniture boxes), read by `homes.py` to build and by `buildings.ts` for collision, floors and doors |
| Editable sources | `assets/blender/flora.blend`, `rocks.blend`, `village.blend` (one scene each, written by the build) |
| Texture atlases | `assets/blender/textures/flora_atlas.png`, `rock.png`, `village_atlas.png` (embedded into the GLBs) |
| Game models | `apps/web/public/models/flora.glb`, `rocks.glb`, `village.glb` |
| Ground textures | `apps/web/public/textures/ground-{grass,soil,sand,rock}.jpg` and `-n.jpg` normal maps |
| Slot registry and loader | `apps/web/src/components/world/assets.ts` (`SLOTS`, `ASSET_FILES`, `preloadWorldAssets`) |
| Placement and drawing | `world.ts` (biomes, `Instancer`), `field.ts` (wheat, grass, flowers in cells), `shaders.ts` (wind, foliage, sky, ground) |
| Look and cost probe | `apps/web/e2e/look3d.spec.ts` (`LOOK=1 pnpm e2e look3d`) |
| Blender previews | `design/blender-previews/` (local, untracked; supporting only) |

## 2. Rebuild

Blender 4.2 or newer (built and tested with 5.2.3 LTS). From the repository root:

```bash
blender -b -P assets/blender/build.py
```

That rebuilds textures, flora, rocks and the village in about 20 s. Pass family names after
`--` to rebuild only some of them; the saved atlases are reused:

```bash
blender -b -P assets/blender/build.py -- village
```

In a running Blender (the Python console, or an MCP client), the same script works without
touching the open file; each family gets its own scene (`Flora`, `Rocks`, `Village`):

```python
p = r'D:/Catan/assets/blender/build.py'
exec(compile(open(p).read(), p, 'exec'), {'__file__': p, '__name__': '__main__'})
```

Then reload the walk (the files are fetched once per page). `pnpm verify` and
`pnpm e2e world3d` must pass; `LOOK=1 pnpm e2e look3d` takes screenshots and measures cost.

## 4. How the game uses them

- **Registry.** `ASSET_FILES` maps a slot to `{ file, nodes }`. Several slots share one file, so
  each family is one request and one texture. Remove an entry to fall back to procedural.
- **Loading.** `World3D` calls `preloadWorldAssets()` and builds the world when it resolves
  (at most 10 s; anything still loading is drawn procedurally). The "Building the island…"
  overlay covers it, so nothing pops in. Files are fetched once per page; a variant node is
  re-rooted at the origin (its position in the file is only a Blender layout).
- **Material conventions (by name).** `Owner…` is tinted in the owning player's colour (sails:
  the harbour's colour); any texture is multiplied, so those regions are painted light grey.
  `Leaf…` is alpha-tested (0.5), double-sided, sways, and gets a depth pre-pass (below).
  `Plant…` is double-sided and gets the stalk wind. Other materials are used as loaded.
- **Vertex colours** (`COLOR_0`) carry most colour and the baked occlusion; textures are
  shared atlases. Custom normals on plants and leaf cards point outward and up, so thin parts
  light softly from both sides (`foliage()` keeps the authored normal on back faces).
- **Wind.** Stalk models carry `_wphase` (exported with `export_attributes`; the loader exposes
  it as `_wphase` and the world renames it `wphase`). The vertex shader bends each stalk more
  towards its tip, with gusts travelling in one world direction; trees and shrubs sway above
  1 m. Nothing animates on the CPU. Wind stops under reduced motion and in Lite.
- **Instancing and detail.** Trees, shrubs, rocks, crags, clay banks and stooks are one
  `InstancedMesh` per variant part for the whole island. Wheat, grass and flowers are instanced
  in square cells (`field.ts`): wheat uses the near clumps within about 7 m, `WheatMid` to
  22 m and `WheatFar` beyond; grass and flowers shrink into the ground between 22–30 m and
  30–40 m and cells beyond aren't drawn. Variants are chosen by position or by the world's
  seeded RNG, never the game's.
- **Depth pre-pass.** Each leaf mesh, and each near wheat cell, has a twin that draws first with
  a cheap depth-only shader (same motion; alpha-tested for leaves); the lit pass then shades only
  the front-most leaf or stalk at each pixel. Alpha to
  coverage is off on purpose: the two passes must agree on every texel, or the sky shows as
  bright fringes.
- **Shadows.** Trees, rocks, buildings and props cast; wheat, grass and flowers only receive.
  The far horizon ranges (crags scaled up) neither cast nor receive. The shadow map is redrawn
  only when its box moves (100-texel steps), when pieces change, and every third frame for
  moving casters (sway, sheep, sails); redrawing ~300 casters every frame was the limit.
- **Static props** (barn, kiln, mine, bales) join the existing bake: merged per material across
  the island. Windmills, docks, boats, sheep, pieces and the robber stay separate objects.
- **Collision and grounding** come from each slot's `footprint` and the terrain's own height,
  never from a mesh. Plants keep 1.6 m clear of tile edges, where roads run and buildings stand.
- **Disposal.** Closing the walk disposes every GPU resource it uploaded, cached models included
  (`dispose()` only frees GPU copies; the page cache keeps the data for the next world).
- **Sky, sea and ground** are shaders in code (`shaders.ts`, `world.ts`), not Blender assets: a
  gradient sky with sun disc and noise-painted clouds, a sea coloured by distance to land with a
  moving wave normal and shore foam, and tiling ground detail mixed at two scales.

## 5. Conventions

| Topic | Rule |
|---|---|
| Units | 1 Blender unit = 1 m. A land tile is 14 m centre to corner; a road is one 14 m edge. Eye height 1.7 m above the floor (the walker is 0.7 m wide). Doors 2.1–2.5 m high, 1.05–1.5 m wide (≥ 0.35 m clear past the walker); rooms 2.6 m (cottage, mill) and 3.6 m (hall) to the ceiling; floors 0.24–0.36 m up on a stone plinth; walls 0.26–0.42 m thick. The board is never stretched: a building stands on its corner, its walls clear of the next corner's (≥ 24 m away), and roads stop at its walls. |
| Axes | Model with Z up and the front facing −Y. The glTF exporter (+Y Up) turns that into the game's +Y up, front +Z. No corrective rotations. |
| Origin | Ground contact, centre of the footprint (trees: trunk base; dock: shore end; boat: waterline; windmill `Sails`: hub). |
| Transforms | Applied (`export_apply`); a root's own translation is ignored by the game. |
| Colour | Vertex colours are authored in sRGB hex and stored linear (`common.srgb`). Base-colour textures sRGB, normal maps linear. |
| Materials | Principled BSDF; base colour = image × colour attribute (the exporter maps it to `baseColorTexture` + `COLOR_0`). Alpha clip via a Greater Than node (exports `alphaMode: MASK`). |
| Atlases | Regions are listed in `textures.py` (`FLORA`, `VILLAGE`). Atlas regions can't repeat, so `aquad` cuts large faces into tiles; leaf cards sample 3 % inside their region so mipmaps don't bleed in a neighbour. |
| Images in GLBs | PNG only where alpha is needed (flora); rocks and village export JPEG (q88). No KTX2, Draco or meshopt: no decoders are set up. |
| Animated nodes | Sheep: `Head`, `LegFL`, `LegFR`, `LegBL`, `LegBR`, `Tail`, origins at the joints. Windmill: `Sails`, turning about its local Z (glTF). Doors: `<Building>Door` (hall: `HallDoorA`, `HallDoorB`), origin on the hinge at floor level, leaf along local +X when closed; the game swings it about +Y. |
| Rooms | Walls are thick solids (inner and outer faces, reveals round every opening), never double-sided. Inside faces and furniture use the `Interior` material; furniture and props sit in the `<Building>Interior` child, which the game hides beyond 34 m. Collision comes from `buildings.json`, not the meshes. |

## 6. Budgets

Measured on the owner's laptop (Intel UHD, the GPU Chrome picks by default) with
`LOOK=1 pnpm e2e look3d`, 1440 × 900 window, Full graphics. "GPU" is the time per frame from
back-to-back renders each forced to finish; it reads high in absolute terms (no overlap
between frames) but compares runs well. The original procedural walk was measured the same way,
at the same seed and viewpoints.

Result (full table in DECISIONS #31): every standard view costs less GPU time than the
procedural walk did (for example inside the wheat 26.0 → 20.5 ms, forest edge 23.9 → 18.0 ms,
elevated 25.5 → 20.8 ms) and holds 60 fps; 420k–760k triangles (wheat ~1.1 M including its
pre-pass) and 290–620 draw calls per frame.
Lite holds 60 fps everywhere at 6.5–11.9 ms. Download: 3.1 MB of models and 0.8 MB of ground
textures, fetched once per page when the walk first opens.

Rules of thumb that held:

- Leaf cards: ~6 cards per cluster, 11–12 clusters per broadleaf. Every extra layer of cards
  costs fill rate in the forest view, the most expensive one.
- Near wheat clumps under ~400 triangles; most of the wheat cost is overdraw from the clumps
  within a few metres (hence their depth pre-pass), not triangles.
- Instanced slots are drawn hundreds of times: add triangles to buildings before plants.
- Texture memory: three 1024 px atlases, one 512 px, four 512 px ground pairs (~15 MB of GPU
  memory with mipmaps).

## 7. Add or change a model

1. Edit the family's script (or add a builder) and rebuild (§2). Keep the conventions (§5).
2. For a new slot: add it to `AssetSlot`, `SLOTS` (size, footprint, mode, shadows) and
   `ASSET_FILES` in `assets.ts`, then use it where the world places that thing (`this.model(slot)`
   with the procedural fallback beside it). Static props can use `this.prop(slot, fallback)`.
3. Check in the browser: `LOOK=1 LOOK_OUT=design/look3d/mine pnpm e2e look3d` writes
   screenshots and costs for the standard views; walk the island with `pnpm dev`.
4. Run `pnpm verify` and `pnpm e2e world3d` (it fails on any console warning, including a
   model that failed to load).

## 8. Known limits

- The Blender scenes are generated, not hand-sculpted: shapes come from bmesh operations
  (fracture cuts, lofts, lathes, cards), detail from vertex colours and small atlases.
- Blender previews (EEVEE) don't match the game exactly; the browser is the reference.
- Settlements and cities face the most inviting tile at their corner (a wheat field first, then
  pasture, hills, forest, mountains, desert); their plinths assume the flat ground at tile edges.
  Plants and rocks inside a building's clearing are hidden (scaled to nothing) while it stands.
- Wheat swaps detail by 7 m cells, so a careful eye can see a cell change at the near/mid
  boundary while walking.
